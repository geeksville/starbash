# Publish Starbash Images to GitHub Pages

Starbash can generate a public, shareable website from your processed image
repositories and publish it to GitHub Pages. Publishing creates or updates the
public `starbash-public` repository in your personal GitHub account.

The local site generator does not require GitHub credentials or network access.
GitHub access is needed only when publishing remotely.

## Prerequisites

- A (free) GitHub account. (If necessary the tool will show you how to create an account)

Process your images before publishing, for example:

```text
sb process auto
```

## Publish the site

Run:

```text
sb publish github
```

Starbash will:

1. Walk you through github account creation and authorizing starbash to create repos in your account.
2. Regenerate and validate the local site.
3. Create `starbash-public` if it does not already exist.
4. Wait for the Pages deployment to complete.

Only the `gh-pages` branch is changed. Each publication is a fresh orphan
commit, so files from an earlier publication are not retained unless they are
regenerated by the current site build.

## Preview locally (optional)

You can optionally generate and view your website even without github.

Regenerate the local GitHub Pages-compatible site with:

```text
sb publish github rewrite
```

The generated site is kept at:

```text
~/.local/state/starbash/publish/site
```

The exact location may vary by operating system. Use the existing local preview
workflow, if configured:

```text
just site-view
```

Local generation is independent of GitHub authentication. It does not create a
repository or upload anything.

## GitHub Pages URL

The published site normally appears at:

```text
https://YOUR-GITHUB-USERNAME.github.io/starbash-public/
```

GitHub Pages deployment can take a few minutes. Starbash waits for the
available deployment status and prints the URL when the publication completes.
If the URL is not immediately available, open it again after the deployment
finishes.

## What is published

Starbash publishes generated files from the local site directory, including:

- target pages;
- generated charts;
- target hero or thumbnail images

## Sign in again

Use `--login` to force GitHub authentication:

```text
sb publish github --login
```

This is useful when:

- the saved credential was revoked or expired;
- you want to publish from a different GitHub account; or
- GitHub reports insufficient permissions.

GitHub uses a device authorization flow. Starbash displays a verification URL
and one-time code. Press Return when prompted to open the verification page;
the browser may open in front of your terminal. If the browser does not open,
visit the displayed URL manually and enter the code. Starbash never asks for or
displays your GitHub password, and does not print access token contents.

On the first sign-in, GitHub may also ask you to install or authorize the
Starbash GitHub application for your personal account. 

## Troubleshooting

### No processed repository

Run `sb process auto` first and verify that Starbash has at least one processed
repository configured for publishing.

### Authentication failed

Retry with:

```text
sb publish github --login
```

Complete the device flow before its code expires. If GitHub reports a
permission problem, confirm that the authenticated account can create public
repositories and manage GitHub Pages.

## Related commands

```text
sb publish github rewrite              # Generate the local site only
sb publish github --dry-run            # Validate and show planned upload
sb publish github                      # Publish using saved credentials
sb publish github --login              # Reauthenticate, then publish
```

The older commands `sb publish github init` and `sb publish github upload` are
not part of the supported interface.
